EnhancementHammerExp

Experience one enhancement hammer gives an equipment in ItemEnhancement (EnhancementCostSheetV3 hammer rows). target_id is the hammer item id (600301~600308), so grades can get different multipliers.

The adjusted experience is stored on the equipment like any other experience: the equipment ends up exactly as if it had gathered that much normally, so it neither owes the boost back on its next enhancement nor is worth less as a material. The result is kept between the configured experience and ItemEnhancement.MaxHammerExpBoostFactor times it — a row can only raise it. See ItemEnhancement.GetHammerExp.

Patch a row only after a client that previews with the adjusted experience is released: an old client shows a lower target level and a lower NCG cost than the action charges (cost follows the level reached), so an avatar holding only the shown NCG fails, and it lets players add more hammers than the max level needs. 

public const string EnhancementHammerExp = "ENHANCEMENT_HAMMER_EXP"

StageItemReward

Material item rewards of an adventure stage clear (HackAndSlash, HackAndSlashSweep). target_id is the StageSheet stage id, so 1~300 covers stages 1 through 300. Event dungeon stages are not covered.

Applied per clear to the count of each distinct item after the items are drawn, so the random draws are the same as without the row: MUL 2 grants exactly twice each drawn item and ADD 1 one more of each. See StageSimulator.GetBoostedItemRewardCount.

Boosted items are ordinary rewards everywhere else too: they count toward collect quest progress, and a circle stays tradable.

Rounding is down, per item id per clear, with one exception: a MUL above 1 turns an item drawn once in a clear (how most stages drop) into at least 2, so MUL 1.5 grants 2 of a single drop. A count of 2 or more keeps the plain floor (MUL 1.2 on 2 stays 2, MUL 1.5 on 2 becomes 3); this is not a general "at least one more". ADD and a MUL of 1 or below are unaffected. Beware that any MUL just above 1 (e.g. MUL 1.01) also turns a single drop into 2 — effectively a 100% boost for those items, however small the value. StageFavReward amounts are large and always plainly floored. 

public const string StageItemReward = "STAGE_ITEM_REWARD"

SummonRuneEnhancementCrystalCost

Crystal cost of one RuneEnhancement try, per RuneCostSheet level, for summonable runes only: a rune whose id is a recipe id of any RuneSummonSheet row, whatever its ratio and whether or not that group is currently sold. Other runes are never adjusted. The summon pool is read from the chain when the try is evaluated, so a rune added to or removed from RuneSummonSheet gains or loses the adjustment with it.

target_id is the rune level the try attempts to reach — the current level plus one — so 1~50 adjusts the tries from level 0 up to level 50. It cannot narrow the row to particular rune ids. The adjusted cost never exceeds the sheet's cost and never drops below 1 while the sheet's cost is positive. NCG cost and success rate are not adjustable. 

public const string SummonRuneEnhancementCrystalCost = "SUMMON_RUNE_ENHANCEMENT_CRYSTAL_COST"

SynthesizeRequiredCount

required_count of a SynthesizeSheet grade — how many materials one synthesis consumes. target_id is the material grade id (grade_id, e.g. 1~4), and a row applies to every item_sub_type of that grade alike. The adjusted count never drops below 1 — which keeps synthesis from being free, not from being cheap: a typo such as MUL 0.06 brings every grade down to 1, so keep values within the range planning intended.

Patch a row only after a client that picks materials by the adjusted count is released: the action still requires the material count to be a multiple of it, so a client choosing by the configured count fails every synthesis while the row is active.
