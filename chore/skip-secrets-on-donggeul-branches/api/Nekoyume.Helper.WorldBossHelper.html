MaxWorldBossRewardBoostFactor

Upper bound of a WorldBossBattleReward, WorldBossKillReward or WorldBossRankReward row: each boosted amount never exceeds this many times the amount drawn, whatever the row's op and value. It bounds a mistyped value (e.g. a block index pasted into the value cell) to a fivefold over-reward and keeps several boosted amounts added to one inventory slot from overflowing.

public const long MaxWorldBossRewardBoostFactor = 5

ApplyRewardBoost(Row, int)

Applies a BoostScheduleSheet row to one granted amount of a world boss reward: the count of one drawn rune, the crystal or the circles.

public static int ApplyRewardBoost(BoostScheduleSheet.Row rewardBoost, int amount)

Parameters

rewardBoost BoostScheduleSheet.Row

The row to apply, or null for none.

amount int

The amount the reward row and the draws grant.

Returns

int

amount unchanged when there is no row or nothing is granted; otherwise Apply(int) of it, capped at MaxWorldBossRewardBoostFactor times amount. A result of 0 means the amount is not granted at all.

Remarks

A boost adjusts what a reward grants but never adds a kind the row does not grant — a row with no crystal stays without crystal under ADD — since a reward that exists only during an event reads as one taken away when the event ends. ADD applies to every amount separately, i.e. once per distinct rune drawn; use MUL to scale a reward as a whole. The cap applies to ADD too, so ADD 10 on a single drawn rune grants 5, not 11. Lowering is not bounded: a MUL below 1 or a negative ADD still lowers an amount, down to 0.
