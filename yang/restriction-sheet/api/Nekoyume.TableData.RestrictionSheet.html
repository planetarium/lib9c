Class RestrictionSheet

Declares what a given item or currency may not be used for, so that a restriction can be adjusted with patch_table_sheet instead of a headless and client release.

A row targets either an item id (numeric key) or a currency ticker (non-numeric key). Which one is looked up is decided by the call site — a market action already holds an item id or a ticker — so the sheet needs no discriminator column.

Columns: key, market_registrable, synthesize_material. The first governs the market registration path only — a fungible item can still reach another account through a garage or by being wrapped into a currency, so a row here does not make its target account bound by itself. The second closes the conversion path that would otherwise turn a restricted item into an unrestricted one.

An empty cell means "unspecified" and leaves the behavior that predates this sheet untouched. An unparsable cell is read as false(= restricted) on purpose: a typo then fails toward blocking, which is recoverable, rather than toward leaking. ValidateCsv(string) rejects such a cell at patch time so it should not reach the chain in the first place.

A key is an item id, not an item instance, so a row applies to every copy that exists — give a restricted item a new id rather than reusing one players already hold. A false market_registrable also stops ReRegisterProduct, leaving an existing seller able to cancel but not to reprice, and it does not retract listings that are already up: BuyProduct does not consult this sheet, so a restriction added after the fact still needs those products cancelled. A false synthesize_material only stops the item from being consumed as a material — an item that must not be handed out by synthesis is kept out of the result pool by leaving it out of SynthesizeWeightSheet, which is a separate sheet from this one.

Callers must tolerate the sheet being absent — it reaches an existing chain only by patch_table_sheet, so loading it as a required sheet would fail every affected action until each chain is patched. Absence has to fall back to the restrictions that are still hardcoded, which is also what keeps re-evaluation of pre-patch blocks identical.
