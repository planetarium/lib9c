Keeps what each world-open id means fixed across table patches. The first patch that carries an id records its identity; a later patch that gives the id a different identity is rejected. An id may be dropped from the sheet (retired), but its record stays, so it can only come back with the same identity. To fix a wrong rule, drop it and add a new id.

Remarks

Counter values and confirmations are keyed by id, so changing what an id means would carry them over to a different rule: a counter would keep counts of something else, and a new opening reusing a confirmed id would open without its conditions. The identity is:

  • GlobalCounterSheet: every column (type, target range, minimum level).
  • WorldOpenSheet: world_id and stage_end. The block window and the prerequisite stay adjustable; the prerequisite follows the stage_end line, so it has to change when an opening is inserted below.
  • WorldOpenConditionSheet: per open_id, which counters are grouped together. Group numbers and row order do not matter; thresholds stay adjustable.

The recorded strings are part of the chain state: changing their format (adding a column, renaming a GlobalCounterType, reordering fields) would make every recorded id mismatch and reject every later patch of that sheet. Keep the format, or compare against the old format as well when it has to change. The tests pin it.
